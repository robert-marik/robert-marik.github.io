Praktický přehled příkazů systému Git: základy, větve, porovnávání změn,
porovnání lokálního repozitáře se serverem, historie po merge a vracení
změn. Předpokládá se základní znalost příkazové řádky. V příkladech je
hlavní větev pojmenovaná `main` (ve starších repozitářích může být
`master`) a vzdálený repozitář `origin`.

## 1. Základy

```bash
git init                      # založit nový repozitář v aktuálním adresáři
git clone <url>               # naklonovat existující repozitář
git remote -v                 # seznam vzdálených repozitářů

git status                    # stav pracovního adresáře
git status -sb                # stručně + info o větvi a předstihu/zpoždění vůči serveru
git add soubor.txt            # přidat soubor do přípravné oblasti (staging)
git add -p                    # přidávat změny po kouscích (interaktivně)
git commit -m "Popis změny"   # vytvořit commit
git commit -am "Popis"        # add + commit všech SLEDOVANÝCH souborů
git commit --amend            # upravit poslední commit (zpráva / přidat soubory)

git fetch                     # stáhnout změny ze serveru, NIC nemění v pracovním adresáři
git pull                      # fetch + merge (stáhnout a sloučit)
git pull --rebase             # fetch + rebase (lineárnější historie)
git push                      # odeslat commity na server
git push -u origin main       # první push větve + nastavení sledování (upstream)
```

> **Tip:** `git fetch` je bezpečný. Nejdříve ho spusťte, podívejte se, co
> přišlo, a teprve potom slučujte.

## 2. Větve

```bash
git branch                    # seznam lokálních větví
git branch -vv                # + sledovaná větev na serveru a předstih/zpoždění
git branch -a                 # včetně vzdálených větví
git switch nazev              # přepnout na větev
git switch -c nova-vetev      # vytvořit větev a přepnout na ni
git branch -d nazev           # smazat (jen když je sloučená)
git branch -D nazev           # smazat natvrdo
git push origin --delete nazev  # smazat větev na serveru
git merge nazev               # sloučit větev do aktuální
git merge --abort             # zrušit rozdělaný merge (konflikty)
git branch --merged           # větve už sloučené do aktuální
```

## 3. Diff – porovnání změn

```bash
git diff                      # změny v pracovním adresáři (ještě nepřidané)
git diff --staged             # změny připravené k commitu (= --cached)
git diff HEAD                 # vše: staged + unstaged proti poslednímu commitu
git diff commitA commitB      # rozdíl dvou commitů
git diff main..feature        # rozdíl dvou větví (totéž jako git diff main feature)
git diff main...feature       # změny na feature od společného předka (jako v pull requestu)
git diff HEAD~3 -- soubor.txt # rozdíl jednoho souboru proti stavu o 3 commity zpět
```

### Možnosti formátu diffu

| Přepínač | Co dělá |
| --- | --- |
| `--word-diff` | zobrazí změny po slovech (`[-staré-]{+nové+}`) |
| `--word-diff=color` | po slovech jen barvou, bez závorek |
| `--color-words` | zkratka pro word-diff v barvách (nejčitelnější) |
| `--word-diff-regex=.` | po jednotlivých znacích |
| `--stat` | přehled: které soubory a kolik řádků se změnilo |
| `--shortstat` | jen celkový souhrn (počet souborů, +/-) |
| `--numstat` | počty řádků strojově (přidáno, odebráno, soubor) |
| `--name-only` | jen názvy změněných souborů |
| `--name-status` | názvy + typ změny (A přidán, M změněn, D smazán, R přejmenován) |
| `-w` | ignorovat všechny bílé znaky |
| `-b` | ignorovat změny v množství bílých znaků |
| `--ignore-blank-lines` | ignorovat prázdné řádky |
| `--ignore-cr-at-eol` | ignorovat rozdíl konců řádků (CRLF/LF) |
| `-U10` | 10 řádků kontextu místo výchozích 3 |
| `--diff-filter=M` | jen určité typy změn (A, M, D, R…) |
| `--minimal` / `--patience` / `--histogram` | jiné algoritmy, někdy čitelnější diff |
| `--color-moved` | zvýrazní přesunutý kód (místo smazaného + nově přidaného) |
| `--check` | najde problémy s bílými znaky a zbylé značky konfliktů |

```bash
git diff --color-words                   # nejčastější: po slovech v barvách
git diff --stat main..feature            # co se změnilo mezi větvemi
git diff --name-status HEAD~5            # co se změnilo za posledních 5 commitů
git difftool                             # otevře grafický nástroj (nutno nastavit diff.tool)
```

## 4. Porovnání se serverem (lokální vs. vzdálený)

Začněte vždy tímto příkazem. Aktualizuje informace o serveru, ale nic neslučuje:

```bash
git fetch origin
```

### Rychlý přehled

```bash
git status -sb                # např.: ## main...origin/main [ahead 2, behind 3]
git branch -vv                # totéž pro všechny větve
git rev-list --left-right --count HEAD...origin/main
# výstup "2   3" = 2 commity mám jen já, 3 commity má jen server
```

### Jsou kódy stejné? (bez stahování)

```bash
git ls-remote origin main     # hash větve na serveru
git rev-parse HEAD            # hash mého aktuálního commitu
# Stejný hash = stejný kód a stejná historie.
```

### Které commity má server a já ne

```bash
git log HEAD..origin/main --oneline            # co na serveru přibylo (ještě nemám)
git log --oneline --graph HEAD..origin/main
```

### Které moje commity server nemá (neodeslané)

```bash
git log origin/main..HEAD --oneline            # lokální commity, které nejsou na serveru
git cherry -v                                  # totéž vůči sledované větvi (upstream)
```

### Obojí najednou

```bash
git log --left-right --oneline --graph HEAD...origin/main
# '<' = jen lokálně, '>' = jen na serveru
```

### V čem se kód liší (obsah souborů)

```bash
git diff origin/main                  # pracovní adresář vs. server
git diff HEAD origin/main             # jen commitnutý stav vs. server
git diff --stat HEAD origin/main      # přehled souborů
git diff HEAD...origin/main           # co na serveru přibylo od místa, kde se větve rozešly
git diff origin/main...HEAD           # co jsem přidal já od rozchodu
git diff --color-words origin/main -- soubor.txt   # jeden soubor po slovech
```

> **Pozor:** `origin/main` je jen lokální kopie stavu serveru z posledního
> `fetch`. Bez čerstvého `git fetch` můžete porovnávat se zastaralými daty.

## 5. Historie po merge – kdo a co odkud přišlo

### Graf

```bash
git log --graph --oneline --decorate           # základní graf
git log --graph --oneline --decorate --all     # včetně všech větví
git log --graph --pretty=format:'%C(yellow)%h%C(reset) %C(green)%an%C(reset) %C(auto)%d%C(reset) %s'
git log --graph --oneline --first-parent       # jen "páteř" hlavní větve, merge jako jeden uzel
```

### Co přinesl poslední merge

```bash
git log --oneline ORIG_HEAD..HEAD              # hned po merge/pull: co nového přibylo
git log --oneline HEAD^1..HEAD^2               # commity z připojené větve (druhý rodič merge commitu)
git show --first-parent HEAD                   # změny merge commitu proti hlavní větvi
git diff HEAD^1 HEAD --stat                    # souhrn změn, které merge přinesl
```

### Filtrování

```bash
git log --merges --oneline                     # jen merge commity
git log --no-merges --oneline                  # bez merge commitů
git log --oneline main..feature                # commity na feature, které nejsou v main
git log --format='%h %an %ad %s' --date=short  # kdo a kdy
git branch --contains <hash>                   # ve kterých větvích je commit
git name-rev <hash>                            # jméno větve/tagu u commitu
```

Hezký graf jako alias:

```bash
git config --global alias.lg "log --graph --pretty=format:'%C(yellow)%h%C(reset) %C(green)%an%C(reset) %C(auto)%d%C(reset) %s' --all"
# použití: git lg
```

## 6. Vracení změn

### Změny v souborech (necommitnuté)

```bash
git restore soubor.txt              # zahodit lokální úpravy souboru (NEVRATNÉ)
git restore --staged soubor.txt     # vrátit soubor ze staging zpět (úpravy zůstanou)
git clean -nd                       # nejdříve: co by se smazalo (zkouška nanečisto)
git clean -fd                       # smazat nesledované soubory a složky
git stash                           # odložit rozdělanou práci
git stash -u                        # včetně nesledovaných souborů
git stash list                      # seznam odložených
git stash pop                       # vrátit poslední odložené a smazat ze stashe
```

### Zrušení commitu, který ještě NEBYL odeslán

Historii je bezpečné přepisovat, protože ji nikdo jiný nemá.

```bash
git reset --soft HEAD~1     # zruší commit, změny zůstanou ve staging
git reset HEAD~1            # zruší commit, změny zůstanou v souborech (mixed, výchozí)
git reset --hard HEAD~1     # zruší commit I změny (NEVRATNÉ, viz reflog níže)
git reset --hard HEAD~3     # zruší poslední 3 commity
git commit --amend          # jen opravit poslední commit (zprávu / přidat zapomenutý soubor)
```

### Zrušení commitu, který UŽ BYL odeslán

**Doporučeno – `revert`** (nepřepisuje historii, vytvoří nový commit, který změny vrátí):

```bash
git revert <hash>           # vrátí změny konkrétního commitu
git revert HEAD             # vrátí poslední commit
git revert HEAD~2..HEAD     # vrátí poslední dva commity (HEAD~1 a HEAD)
git revert -m 1 <hash>      # vrácení merge commitu (-m 1 = hlavní větev je první rodič)
git push
```

**Jen výjimečně – přepsání historie** (pouze na vlastní větvi, kterou nikdo jiný nepoužívá):

```bash
git reset --hard HEAD~1
git push --force-with-lease     # bezpečnější než --force: selže, pokud na serveru někdo něco přidal
```

> **Pozor:** Na sdílených větvích (`main`, `develop`) historii
> nepřepisujte. Ostatním se tím rozbije jejich lokální repozitář.

### Záchrana, když se něco pokazí

```bash
git reflog                      # historie, kam ukazoval HEAD (i po reset --hard)
git reset --hard HEAD@{2}       # vrátit se do stavu z reflogu
git branch zachrana <hash>      # vytvořit větev na "ztraceném" commitu
```

## 7. Konflikty při merge a rebase

```bash
git status                    # ukáže soubory v konfliktu
# upravte soubory (odstraňte <<<<<<<, =======, >>>>>>>), pak:
git add soubor.txt
git commit                    # dokončí merge (u rebase: git rebase --continue)
git merge --abort             # vzdát to a vrátit stav před merge (u rebase: git rebase --abort)
git restore --ours soubor     # vzít při konfliktu verzi z aktuální větve
git restore --theirs soubor   # vzít verzi z připojované větve
```

> **Pozor:** Při `git rebase` jsou role prohozené: `--ours` je větev, na
> kterou se přeskupuje (např. `main`), a `--theirs` jsou vaše přenášené
> commity.

## 8. Další užitečné příkazy

### Prohledávání historie

```bash
git log --oneline -10                  # posledních 10 commitů
git log -p soubor.txt                  # historie jednoho souboru včetně změn
git log --follow soubor.txt            # i přes přejmenování
git log -S"text"                       # kdy se přidal/odebral daný řetězec
git log --author="Jmeno" --since="2 weeks ago"
git show <hash>                        # detail commitu
git blame soubor.txt                   # kdo naposledy změnil který řádek
```

### Hledání commitu, který zavedl chybu (bisect)

```bash
git bisect start
git bisect bad                         # aktuální stav je chybný
git bisect good <hash>                 # tento starší commit byl v pořádku
# Git přepíná commity, u každého otestujte a zadejte good/bad
git bisect reset                       # konec, návrat na původní větev
```

### Přenášení a úprava commitů

```bash
git cherry-pick <hash>                 # přenést jeden commit do aktuální větve
git rebase main                        # přenést moje commity nad aktuální main
git rebase -i HEAD~4                   # interaktivně: sloučit (squash), přeházet, přejmenovat commity
git commit --fixup <hash>              # opravný commit ke staršímu commitu, poté:
git rebase -i --autosquash <hash>~1    # oprava se automaticky sloučí s původním commitem
```

### Tagy

```bash
git tag v1.0                           # lehký tag
git tag -a v1.0 -m "Verze 1.0"         # anotovaný tag
git push origin v1.0                   # odeslat tag (nebo --tags pro všechny)
```

### Nastavení

```bash
git config --global user.name "Jméno Příjmení"
git config --global user.email "mail@example.com"
git config --global init.defaultBranch main   # název hlavní větve u nových repozitářů
git config --global pull.rebase true          # pull = fetch + rebase jako výchozí
git config --global core.autocrlf input       # (Linux/Mac) řeší konce řádků
```

## 9. Soubor .gitignore

```text
*.log
node_modules/
__pycache__/
.env
```

Pokud už soubor Git sleduje, samotné přidání do `.gitignore` nestačí.
Odeberte ho ze sledování (soubor na disku zůstane) a změnu commitněte:

```bash
git rm --cached soubor
git commit -m "Přestat sledovat soubor"
```
